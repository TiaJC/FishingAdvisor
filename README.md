一个 Android 原生应用：获取当前位置，拉取逐小时气象，按**多因子加权模型**算出 0–100 的钓鱼指数，
并结合**目标鱼种**给出钓位、水深、饵料与钓法建议。

核心交互是**选时**——在时间轴上点任意一个小时，整页的指数、评分构成与建议都会按那一刻重算，
所以"明天早上六点值不值得去"可以直接查，而不只能看当前。

## 评分模型

```
总分 = Σ(因子得分 × 权重) ÷ 100      因子得分 0–100，权重合计 100
```

| 因子 | 默认权重 | 评分依据 |
| --- | ---: | --- |
| 气压趋势（近 3h） | 25 | 平稳/缓升最好；骤降（≤ −3 hPa）几乎停口 |
| 气压绝对值 | 20 | 1010–1022 hPa 最佳 |
| 风力 | 15 | 蒲福 2–3 级满分，≥6 级 30 分以下 |
| 风向 | 10 | 东/东南风高，南/西南风低（**地域性强，可关**） |
| 水温（估算） | 10 | 按鱼种最适区间评分，偏离越多分越低 |
| 降水 | 10 | 无雨满分，大雨 12 分 |
| 时段 | 10 | 日出/日落前后为黄金窗口，具体节律因鱼种而异 |

| 总分 | 等级 |
| --- | --- |
| 80–100 | 极佳 |
| 65–79 | 良好 |
| 50–64 | 一般 |
| 35–49 | 较差 |
| 0–34 | 不宜 |

**权重存相对值、计分时归一化**，所以滑块怎么拖总分都不会溢出或失真；全部拖到 0 时兜底均分而非除零。
界面同时显示原值与归一化后占比（如 `20 → 20.0%`），让直觉和实际计算对得上。

### 鱼种修正
- **水温替代气温**：鱼是变温动物，行为由水温决定。Open-Meteo 不给水温，用
  `0.6 × 过去 24h 均温 + 0.4 × 当前气温 − 1.0℃` 估算，界面明确标注是估算值。
- **气压项按耐低氧能力缩放**：鲢鳙极不耐低氧，低气压惩罚加重 40%；黑鱼、鲶鱼有辅助呼吸器官，惩罚减半。
- **时段按活动节律分档**：鲶鱼夜间 100 分、白天 45 分；草鱼反过来。

### 13 个鱼种
鲫、鲤、草、鲢鳙、青、鲈、翘嘴、黑鱼、鲶、黄颡、罗非、鳊 + 不限鱼种。
每个物种记录水层、最适/可摄食水温、耐低氧等级、活动节律、偏好结构、饵料、钓组、钓法。

## 算法的可靠性（建议先读这段）

各因子的证据强度**差别很大**，应用内「百科 → 证据」页做了分级。这里如实列出：

| 因子 | 证据强度 | 说明 |
| --- | --- | --- |
| 水温 / 溶氧 | **强** | 变温动物代谢由水温直接决定，有实测数据（鲤 8–14℃ 消化需 20h，26–30℃ 只需 4–6h） |
| 风力 / 风浪 | **中** | 风浪增氧与饵鱼被推向下风岸，机理清楚，但阈值靠经验 |
| 时段 | **中** | 晨昏窗口有行为学依据，具体时长是经验值 |
| 降水 | **中** | 小雨增氧、大雨停口，与安全风险相关 |
| 气压趋势 | **弱–中** | **存在真实分歧**：国内说"骤降停口"，欧美主流说"锋面前缓降是进食高峰"，取决于季节温度背景 |
| 气压绝对值 | **弱** | 气压 1020→990 hPa 对饱和溶氧的影响仅约 3%，相当于水温升 1.5℃。它更多是**天气系统的代理指标** |
| 风向方位 | **最弱** | 物理上风向本身不影响鱼，起作用的是风引起的水体混合与饵鱼迁移。"西南风钓鱼空"是中国东部季风区的气候口诀，换气候区即失效。**可在设置里关闭** |

**气压类合计 45 的权重是沿用垂钓界通行经验，不是严格实验结论。** 如果你在本地发现明显不符，
用设置页的滑块调低它、把水温调高，通常更贴近实际。

水温是估算值，夏季表层与 3 米以下能差 3–6℃，这是模型最大的误差源。

## 已知取舍

- 底部导航图标用 emoji 而非矢量图标库——工程没引入 `material-icons-extended`，加依赖不如直接省掉。
- 收藏只存坐标与名称，不存天气数据：切换时重新拉取，避免收藏夹因数据过期而失真。
- 收藏判定用 500 米距离阈值而非坐标精确比对——定位本身有几十米误差，精确比对永远判不上已收藏。
- 组合时间轴刻意不用 Canvas 文本 API（`drawText(TextMeasurer)` 需 opt-in 实验性 API），
  刻度与标签全部用 Compose `Text` 叠加，几何量按 dp 算、Canvas 内再 `.toPx()`，保证两层坐标一致。
